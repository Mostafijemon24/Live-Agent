# Security review — Phase 2 quality gate (2026-10-24)

An independent reviewer (a separate agent with no part in writing the code) audited the Phase 2 code with local, read-only testing. Its findings were cross-checked by the lead: SR-4 and SR-11 were also found and measured independently. Findings were recorded **before** any fix. A status is updated only when a regression test exists and passes; all of them below were verified on 2026-10-24.

Severity scale: Critical / High / Medium / Low / Informational.

| ID | Sev. | Finding | Evidence (observed) | Status |
|---|---|---|---|---|
| SR-1 | High | Per-IP rate limits key on the left-most `X-Forwarded-For`, which the client controls through the Next.js proxy (and uvicorn runs with `--forwarded-allow-ips "*"`). Without XFF, every user shares the web container's IP. | A spoofed XFF reached the API unchanged. 40 rotated-XFF logins: no 429. An unrelated victim got 429 after an attacker's 21 attempts. Spoofed IPs were written to the audit log. | **Fixed** — the API ignores `X-Forwarded-For`. With `TRUST_PROXY_HEADERS=true` it reads only `X-Real-IP`, which Caddy overwrites. uvicorn runs with `--no-proxy-headers`. Per-email register limit added. Production refuses to start without the trusted proxy. Tests: `test_sr1_*`; live check through Next: rotated spoofed XFF still hit 429. |
| SR-2 | Medium | Open redirect after login: `safeNext` checks the raw string, but browsers strip tab/CR/LF (`/%09/evil.example`). | Playwright landed on `http://evil.example/phish` after login. | **Fixed** — shared `sameOriginPath()` (rejects control characters/backslashes, parses, then requires the same origin), used for login `?next=` and notification links. Test: `web/lib/safe-path.test.ts` (17 cases). |
| SR-3 | Medium | Upload type check bypasses: zip with `.exe` named `.docx`; scripts after byte 512 in text; `%PDF-` content named `.hta`, served back as `.hta`. | All accepted with `201`. | **Fixed** — the extension must match the detected type. DOCX/XLSX are opened and checked for OOXML structure, executables/macros/embedded OLE, and entry count/size limits. Text types are scanned in full (chunk-overlap safe) for active content and must be valid UTF-8. Tests: `test_sr3_*`. |
| SR-4 | Medium | Register timing reveals existing accounts (the existing-email path skips Argon2). | Reviewer: 48 ms vs 131 ms median, ranges don't overlap. Lead: 24 ms vs 112 ms. | **Fixed** — the existing-email path does the same Argon2 work, and register/forgot/resend are padded to `AUTH_RESPONSE_FLOOR_MS` (default 400 ms). Test: `test_sr4_*` (all three endpoints; medians within 25 ms, all at or above the floor). |
| SR-5 | Medium | Forgot-password/resend send mail inside the request for known users only: a mail outage returns `500` only for existing emails, plus a timing gap. | SMTP down: existing → `500`, unknown → `202`. Outbox gap ~5–7 ms. | **Fixed** — mail is queued during the request and delivered after the response. Delivery failures are logged with a masked address and never change the response. Test: `test_sr5_*` (SMTP down → 202 for existing and unknown emails). |
| SR-6 | Low (latent) | Role checks are missing on several writes (classification, plan approval, automations, deletion requests). Matters once members/viewers can be invited. | `viewer` could set a file `public` (200), approve a plan (200), create an automation (201). | **Fixed** — central role matrix: viewer = read-only; member = tasks, uploads, deletion requests; owner/admin = plan decisions, classification, automations, integrations, approvals, workspace settings. Test: `test_sr6_*` (viewer and member). |
| SR-7 | Low | Composite tenant FKs are missing on `tasks.automation_id`, `jobs.task_id`, `audit_events.task_id`, `deletion_requests.target_id`. | Cross-workspace rows inserted as `steward_app`: all accepted. | **Fixed** — migration `0003` adds composite FKs on all four columns (additive; applied to existing data). Test: `test_sr7_*`. |
| SR-8 | Low | The approval "binding" is an unkeyed SHA-256 over some fields; displayed fields (risk, data-leaves, consequences, title) are not covered, and anyone with row access can recompute the hash. | Tampered rows were approved (`200`). | **Fixed** — HMAC-SHA256 keyed with `APPROVAL_SIGNING_KEY` (app config, not in the DB), covering every displayed field plus workspace, number and expiry; constant-time comparison. Tests: `test_sr8_*`. |
| SR-9 | Low | No rate limit on audit-producing calls (`/integrations/{key}/connect`, 404 probes). The docs overstate "append-only even for owner" (the owner can disable the trigger). | 400 requests → 400 audit rows, no `429`. Owner disabled the trigger and edited a row. | **Fixed** (limits) / **Documented** (owner) — denied-ID probes are capped at 30 per 10 min per user (429, no further audit rows), and connect has a write limit. SECURITY_AND_PRIVACY.md now says the schema owner can disable the trigger; tamper evidence against the owner needs hash-chaining or an external log (Phase 3). Tests: `test_sr9_*`. |
| SR-10 | Low | Production config guards miss `replace-me` placeholders, `MAIL_BACKEND=disabled`, an untrusted proxy setup, and Compose defaulting `APP_ENV` to development. | `Settings(env=production, …replace-me…, mail_backend=disabled)` accepted. | **Fixed** — production rejects placeholder/dev secrets, a signing key shorter than 32 characters, non-SMTP mail, SMTP without STARTTLS, `http://` origins, disabled rate limits and an untrusted proxy setup. Compose requires `APP_ENV` and `APPROVAL_SIGNING_KEY`. Test: `test_production_config_guards` (10 cases). |
| SR-11 | Low | The web app sends no Content-Security-Policy. | `curl -I /login`: no CSP header. | **Fixed (partial)** — production builds send a CSP (`default-src 'self'`, no external origins, `object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`). `script-src` still needs `'unsafe-inline'` because Next.js has no per-request nonces here; a nonce-based CSP is follow-up work. HSTS comes from Caddy. Test: `web/lib/security-headers.test.ts`; live header verified, e2e passes under the CSP. |
| SR-12 | Low | Display names keep bidi/zero-width/C1 characters (`invoice‮fdp.hta` shows as `…pdf`). The registrant-chosen name appears in the email to an unverified address (phishing text inside a genuine email). | Stored names kept U+202E, U+200B, U+0085. Email began "Hi https://steward-support.evil.example/…". | **Fixed** — control, format (bidi, zero-width), separator and C1 characters are stripped from file names and user names. Verification emails no longer include the registrant-chosen name. Tests: `test_sr12_*`. |
| SR-13 | Info | Event order inside one transaction is non-deterministic (same `now()`, ordered by random UUID) — caused a flaky test. Login doesn't revoke the presented session. The CSRF cookie has no `__Host-` prefix in production. Login lockout DoS (10 attempts / 15 min per email). No separation of duties for self-requested deletions. | Full suite failed once at `test_tasks.py:30`; passes alone. | **Fixed**: event order (identity `seq` columns, migration 0003; suite passed 3× in a row); login revokes the presented session; `__Host-stw_csrf` in production. **Accepted risk (documented)**: per-email login lockout (10 per 15 min, mitigates spraying); self-approval in single-user workspaces. CSRF tokens are not session-bound (double-submit + Origin check retained). |

Checked and found OK by the reviewer: tenant isolation on every ID-taking endpoint and on all list endpoints; session flags, hashing, revocation and expiry; CSRF (missing token, `Origin: evil`, `Origin: null`, suffix-domain origins all rejected); login timing; approval locking, expiry and exact-item confirmation; download headers and CRLF neutralisation; LIKE escaping; mass assignment; no secrets in logs; DB role privileges; private storage permissions; container exposure and non-root users.

Dependency audit (lead): `npm audit` → 0 vulnerabilities; `pip-audit -r requirements.lock` → no known vulnerabilities.

# Security review — Phase 3 agent engine (2026-10-24)

An independent reviewer (separate agent, read-only, localhost only) audited the agent engine after implementation. Findings were recorded here **before** any fix; statuses change only when a regression test exists and passes.

| ID | Sev. | Finding | Evidence | Status |
|---|---|---|---|---|
| P3-SR-1 | High | Sandboxed code runs as namespace-root with capabilities over its own mounts and can `umount2` the tmpfs masks, revealing `.env`, `/root`, and every workspace's stored files. | Observed: unmount of `/home`, the API dir and `/root` returned 0; `.env` became readable. | **Fixed** — after the masks are set up the program starts in a nested user namespace as an unprivileged uid with `no_new_privs` and no inheritable capabilities, so the inherited mounts are locked and cannot be unmounted or remounted. Test: `test_sandbox_cannot_unmount_its_masks_or_remount_root` (umount2 on every mask and a root remount fail; CapEff = 0). |
| P3-SR-2 | Medium | Approvers can't see full step arguments (truncated to 120 chars; code up to 8000); title/consequences are model-written. | Code review. | **Fixed** — plan steps expose the exact `args` and `args_hash`; approvals list every argument in full; the approval title is server-written and the model's goal is labelled "AI-written". UI shows "Exact arguments" as plain text. Tests: `test_approver_sees_the_full_arguments`, `StepPolicy.test.tsx`. |
| P3-SR-3 | Medium | Redaction misses `DB_PASSWORD=…`, JSON `"password": "…"`, double-encoded JSON, `aws_secret_access_key`, `Authorization: Basic`. | Observed: unredacted. | **Fixed** — credential pattern handles prefixes (`DB_PASSWORD`), quotes and escaped JSON quotes, `access_key`/`private_key`, and replaces only the value (JSON stays valid); Basic auth added. Test: `test_redaction_formats_from_review` (6 cases). |
| P3-SR-4 | Medium | Lease loss / `retry_of_same` / `QueueFull` inside handlers can re-run an approved step without full re-verification; `complete`/`fail` don't check ownership; heartbeat thread dies silently. | Code review (race not reproduced). | **Fixed** — `complete`/`fail` and runner phases A/C require the job to still be owned by this worker (`still_owned`); a failed or lost heartbeat discards the result; retries re-run full `verify_binding` (only the consumed flag is tolerated, never for non-idempotent tools); follow-up jobs bypass backpressure (`internal=True`). Tests: `test_only_the_owning_worker_can_finish_a_job`, `test_stale_tool_job_owner_does_not_run_the_step`, `test_internal_follow_up_jobs_bypass_backpressure`, `test_retry_reverifies_approval_except_consumption`. |
| P3-SR-5 | Medium | `steward_worker` can UPDATE any column of `approval_requests` (revive consumed approvals) and `tasks.data_classification`. | Observed via `\dp`. | **Fixed** — migration 0005: `steward_worker` gets `INSERT` + `UPDATE(execution_state, updated_at)` on approvals and engine-only columns on tasks; a trigger (all roles) makes execution state forward-only and decided status immutable. Tests: `test_worker_cannot_revive_or_redecide_approvals`, `test_worker_cannot_weaken_task_classification`. |
| P3-SR-6 | Medium | Sandbox output is buffered before capping (memory exhaustion of the tools worker); no process-count limit. | Code review. | **Fixed (partial)** — output is read incrementally with a hard cap and the program is killed on overflow; `RLIMIT_NPROC` set (per-namespace, enforced for the non-root production worker; not enforceable when the worker runs as real root, as in this dev container — that sub-test is skipped there); PID namespace + Compose `pids_limit`. Test: `test_sandbox_output_flood_and_fork_bomb_are_contained`. |
| P3-SR-7 | Low | A member's `answer` message during an approval wait skips the pending step. | Code review. | **Fixed** — `answer` is refused (`409 waiting_for_approval`) while a task waits for an approval. Test: `test_answer_cannot_skip_a_pending_approval`. |
| P3-SR-8 | Low | No overall egress deadline (slow-drip responses); abandoned tool threads; proxy mode loses DNS pinning. | Code review. | **Fixed (partial)** — overall response deadline (2× timeout). Proxy mode: documented that the forward proxy must itself block private/metadata ranges. Abandoned tool threads after a timeout remain a known limitation (tools are individually time-bounded). Test: `test_slow_drip_response_hits_the_overall_deadline`. |
| P3-SR-9 | Low | Internal exception text reaches task/step errors shown to users. | Code review. | **Fixed** — unexpected exceptions stay in `jobs.last_error` and logs; users see "internal error (reference: job …)". Test: `test_internal_errors_are_not_shown_to_users`. |
| P3-SR-10 | Low | Global queue cap shared across tenants; unique dedupe per WordPress connect; non-atomic per-workspace running cap; FIFO across tenants. | Code review. | **Partly fixed / accepted** — WordPress verification deduplicated per site per minute; connect is write-rate-limited. Global cap and FIFO across tenants are documented limits for a single-VPS deployment (weighted fair claiming is future work). |
| P3-SR-11 | Info | Storage keys not checked against workspace prefix on read; app role can INSERT `files.deleted_at`; `fec0::/10` treated as public; public-suffix allowlist entries accepted; read-only probe weak; no two-person rule. | Partly observed. | **Fixed**: storage keys must start with the workspace id on every read (`test_storage_key_must_belong_to_the_workspace`); a trigger rejects inserting pre-deleted files for every role (`test_api_role_cannot_insert_pre_deleted_files`); `fec0::/10` blocked; shared hosting suffixes (e.g. `github.io`, `co.uk`) refused in the allowlist (`test_shared_hosting_suffixes_cannot_be_allowlisted`). **Accepted/documented**: no two-person rule; interpreter under `/home` would skip that mask (production image uses `/usr/local`). |
